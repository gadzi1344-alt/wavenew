# Wave — лента на Supabase, хостинг на Vercel

Статический сайт (HTML/CSS/JS без фреймворков) + Supabase для базы, входа и файлов.

## Структура

```
public/            всё, что отдаёт Vercel
  index.html       разметка
  styles.css       стили
  app.js           логика приложения
  config.js        создаётся при сборке из переменных окружения (в git не попадает)
  sw.js            сервис-воркер (установка на экран телефона, офлайн-оболочка)
  manifest.json    PWA-манифест
  icon-*.png       иконки
scripts/build.js   генерирует config.js
db/supabase.sql    схема базы: таблицы, политики RLS, функции, бакет media
vercel.json        сборка, заголовки безопасности, кэш
```

## 1. Supabase

1. Создайте проект на supabase.com.
2. В SQL Editor выполните `db/supabase.sql`. До запуска замените `CHANGE_ME` на свой админ-код (он нужен только для входа под логином `bibnaq`).
3. Authentication → Providers: включите Google и/или GitHub. Для каждого провайдера укажите свои Client ID и Secret из консоли провайдера.
4. Authentication → URL Configuration:
   - Site URL: `https://ваш-проект.vercel.app`
   - Redirect URLs: `https://ваш-проект.vercel.app/**` и при необходимости `http://localhost:3000/**`

Ключ, который используется в приложении, — publishable (anon). Он предназначен для браузера. Защиту данных обеспечивают политики RLS в `db/supabase.sql`, поэтому не отключайте RLS.

## 2. Vercel

1. Загрузите папку в GitHub-репозиторий и импортируйте его в Vercel (Add New → Project). Framework Preset — Other. Настройки сборки подхватятся из `vercel.json`.
2. В Settings → Environment Variables добавьте:
   - `SUPABASE_URL` — адрес проекта, например `https://abcdefgh.supabase.co`
   - `SUPABASE_PUBLISHABLE_KEY` — publishable-ключ из Supabase (Settings → API Keys)
3. Deploy. Каждый последующий push в ветку обновит сайт.

Если переменные не заданы, сборка использует значения по умолчанию из `scripts/build.js` (проект, с которым работало приложение). Для собственного проекта лучше задать свои переменные.

## Локальный запуск

```bash
node scripts/build.js      # создаст public/config.js
npx serve public           # откроет сайт на localhost:3000
```

## Что изменено по сравнению с одним index.html

- Код разделён на `styles.css`, `app.js` и `index.html`, чтобы браузер кэшировал их отдельно.
- Адрес и ключ Supabase вынесены из кода в переменные окружения.
- SQL-схема перенесена в `db/`, её больше не отдаёт сайт.
- Добавлены заголовки безопасности (CSP, X-Frame-Options, Referrer-Policy) и правила кэша.
- Версия Supabase SDK зафиксирована (2.49.4), чтобы обновление библиотеки не сломало сайт.
- Исправлено: двойная загрузка профиля при старте; ошибка при подписке на несуществующего пользователя; ложное отображение галочки в админке при ошибке сохранения; переход в ленту после удаления поста со страницы поста; поиск с символами `%` и `_`; проверка типа и размера загружаемых фото (до 8 МБ); сервис-воркер теперь реально кэширует оболочку; в манифесте исправлено описание.

## Известные ограничения

- Имя `bibnaq` зашито в SQL и в `app.js` как администратор. Чтобы сменить, поменяйте его в обоих местах.
- Сервис-воркер и кэш: после обновления сайта версию в `CACHE` (`sw.js`) стоит поднять, иначе у части пользователей интерфейс обновится не сразу.
